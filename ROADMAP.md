## Summary
- v0.3.0 covers onboarding, day-N change, troubleshooting, on-demand activity lookups, network profiles and compliance policies against Catalyst Center 3.2.2: 95 tools and the `catc_onboard_device` prompt (v0.2.0 had 81 tools, 34 of 38 operator workflows curated; v0.3.0 adds template-to-profile attach), with live tests on real CML devices (r1/r2 cat8000v, sw1/sw2 cat9000v). Everything else is reachable through `catc_api_call`, except 12 multipart/binary operations.
- Biggest gaps: issues, assurance events and the audit log are each queryable, but platform event notifications aren't curated and there is no merged "what happened here recently" view; three workflows still on api_call (AAA/ISE site settings, PnP claim, LAN automation); SWIM distribute/activate is mock-only (no `.bin` image); SDA and wireless are read-only; reports, ITSM and RMA aren't curated; compliance remediation stays on api_call.
- **Now** (✅ v0.3.0) gave the server on-demand activity lookups that need no appliance setup (issues, assurance events, event notifications and audit log, merged by time; pull-only per ADR-003), template-to-profile attach, compliance policy authoring, hardening of known rough edges plus a lab seed/cleanup script, the core v0.3.0 bump and pager clean-up (C1/C5) and the `catc_onboard_device` prompt. Found live: the provisioning API does not apply a profile's Day-N templates (deploy them with `catc_deploy_template`); the `/discoverys` version switch moved to D18.
- **Next** (✅ v0.4.0, 106 tools, 3 prompts) brought ISE integration and site AAA (ISE 3.5 integrated live), the NAC and change-window prompts (both run live), PnP claim (live) and RMA (mock: needs the device image in SWIM). Live SWIM (D12) moved to Later: it needs a cisco.com `.bin`. Webhooks (D7) were dropped: the servers never receive pushed data.
- **Later** is SDA writes, wireless, LAN automation, and reports/ITSM. These are bounded by missing AP/ServiceNow resources (the CML node cap is gone: Enterprise licence, 70 nodes).

## Logs and events (pull-only, ADR-003)
Every tool queries Catalyst Center when called ([ADR-003](https://github.com/dr-stutters/stutters-mcp-core/blob/main/docs/adr/003-no-event-ingestion.md)). No webhooks, syslog subscriptions, pollers or buffers; the history available is what CatC keeps.

| Tool | What it reads | Status |
|---|---|---|
| `catc_list_issues`, `catc_get_issue` | Assurance issues (priority, status, site, device, client MAC) and their suggested actions | ✅ v0.2.0 |
| `catc_list_events` | Assurance events: device syslog, SNMP traps, client onboarding (up to 7 days) | ✅ v0.2.0 |
| `catc_list_audit_logs` | Who changed what, including changes made outside MCP (up to 30 days) | ✅ v0.2.0 |
| `catc_list_event_notifications` (D2) | Platform event notifications (device unreachable, link/OSPF alerts, config drift, reboots, licensing, system health) | ✅ v0.3.0 |
| `catc_recent_activity` (D2) | Issues + assurance events + notifications + audit log for a device or site, merged by time | ✅ v0.3.0 |

- **Users/roles management, backups (create/restore), sensors, smart-account licensing, email/SNMP/SFTP/PagerDuty event destinations**: one-off admin work or not in the lab. Roles are read only for the D17 check.
- **A separate un-provision tool**: CatC 3.x has none. Un-provisioning is deletion, so it stays in `catc_delete_device` (D20).
- **Receiving events in this server** (Event Management webhooks or syslog subscriptions, device syslog/traps): out of scope suite-wide (ADR-003); D7 was dropped. CatC already collects device syslog and traps, and `catc_list_events` / D2 query them on demand.
